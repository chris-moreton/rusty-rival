# Rusty Rival v1.0.74

A raw-speed release: reduce per-node work while preserving fixed-work search results.

## Changes

- Reuse per-ply searched-quiet, searched-capture and deferred-capture buffers with independent ownership per search thread.
- Construct move-verification lists only in the pawn and castling branches that need them.
- Skip cancelling castling-hash XOR updates when castling rights do not change.
- Inline the existing piece-set equality comparison.
- Prefetch the final word of the unchanged transposition-table entry on x86.
- Use an equivalent balanced maximum reduction in the four-lane move picker, preserving tie order.

The network, evaluation scale, pruning parameters, move ordering, tablebase behavior and UCI settings remain unchanged. Reusable buffers retain capacity lazily; if all 251 plies retained 256 entries in all three buffers, storage would be about 1.5 MiB per search thread, plus metadata.

## Measured scope

On one Ryzen 9 5950X, Linux x86-64-v3, fresh matched PGO builds, one thread and Hash 128:

| Workload | Build pair 1 | Build pair 2 |
| --- | ---: | ---: |
| Bench depth 20 | +3.46% | +3.89% |
| 60 positions at depth 16 | +4.22% | +4.83% |

Each comparison used four paired timing blocks. Both independently rebuilt pairs met the frozen acceptance threshold; they are not pooled. A depth-18 diagnostic on pair 2 measured +4.97%. Same-source rebuild controls measured -0.28% on bench and -0.66% on the 60-position workload; results were not adjusted by these controls. Timing intervals describe within-pair measurements, not variation across machines.

## Correctness evidence

The research candidate passed 284 release tests (three existing ignored tests, no exclusions), debug library and scratch-lifecycle tests, Python tests and CI-style checks. Both PGO pairs matched on 80 fixed-node and 60 fixed-depth positions, including nodes, scores, PVs and best moves. Scalar x86-64-v2 builds matched on the same 140 positions and matched their AVX2 counterparts. The 80 fixed-node positions are PGO training positions; the 60-position workload is disjoint from those and bench roots, but was reused from earlier speed research.

These are same-host raw-speed results, not an Elo or cross-platform speed claim. A faster time-limited search can naturally choose a different move because it searches more nodes. Versioned packaging and public-binary verification are separate release gates.
